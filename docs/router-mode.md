# 路由器模式与 Claude 网络异常防护

本教程适合由路由器负责代理或分流、本机不使用 HTTP 代理的网络。Claude China 通过一次独立的 Cloudflare HTTPS 查询判断出口国家或地区；在 Windows 上，通过本启动器或 `claudec` 启动的 Claude 还会在运行期间定期检查国家或地区。WebRTC 保持启用。

## 开始前

- 安装 Claude China v0.4.8 或更新版，并已安装 Claude 桌面应用或 Claude Code。桌面程序和独立安装的 CLI 需要分别更新。
- 确认路由器已经按你的预期处理 Claude 的 HTTPS 和 UDP 流量。关闭 Windows 的系统 HTTP/PAC 代理；不需要为此启动本机代理或开启本机 TUN。
- 保存工作并结束准备切换的受保护 CLI / Playwright 会话。将原有网络防护还原后，旧进程将不再受原规则保护。
- 此处的运行期阻断仅支持 Windows 上的受管 Claude 桌面、Claude Code CLI 和登记的本机 Playwright 浏览器。Codex、Grok 在路由器模式下只进行启动前检查。

## 从已有 TUN 或固定代理防护切换

1. 打开 **设置 → 安全检查 → 系统网络防护**。如果要运行 Claude 桌面，在「保护对象」选择 **Claude**；如果要运行 Claude Code 或它启动的 Playwright，选择 **CLI / Playwright 浏览器**。
2. 对每个要切换的对象，如已有 TUN 或固定 HTTP 代理防护，点击 **还原网络防护**并按 Windows 提示授权。只还原要切换的对象，不必修改其他应用的规则。
3. 在同一页开启 **路由器模式**，建议保留 **无法确认时也阻止启动**，然后点击 **保存设置**。系统 HTTP 代理必须关闭；应用会忽略受管进程中的 HTTP、HTTPS 和 SOCKS 代理环境变量。
4. 在「出口地区检查」选择 **Claude**并点击 **检查环境**。检查通过仅代表本次 Cloudflare 查询的出口国家或地区没有命中禁止名单。检查不会请求 Claude/Anthropic，也不会单独探测 STUN、UDP 或 DNS；目标浏览器 WebRTC、IP 信誉及 Claude 实际服务路线均未验证。
5. 从 Claude China 启动 Claude 桌面，或在「我的终端」中启动 Claude Code 配置。Windows 会请求管理员授权：请使用**当前 Windows 用户**的管理员授权，等待保护验证通过后再启动目标程序。

也可在安装了 `claude-china` 的终端中选择模式并启动 Claude 配置：

```powershell
claudec network-mode router
claudec list
claudec run "你的 Claude 配置名"
```

CLI 命令只切换配置，不会自动还原已经安装的 TUN / 固定代理防护。路由器模式下受管 CLI 不使用 HTTP 代理环境变量，网络路径由操作系统和路由器决定。

## 如何检查运行状态和测试异常

1. 启动受管 Claude 后，在 **安全检查 → 系统网络防护**选择对应保护对象：桌面应用选 **Claude**，受管 CLI 和 Playwright 选 **CLI / Playwright 浏览器**。正常时显示「路由器运行防护已启用」。
2. 在**该受管 CLI 实际启动的本机 Playwright 浏览器**中访问你信任的 WebRTC 检测页面，分别核对网页 HTTPS 出口与 WebRTC 的公网候选地址。独立打开的普通浏览器不能代表这次受管会话；不要把检测页面上的 IP、账号信息或诊断结果随意公开。
3. 在方便且保存工作后，可暂时使 Cloudflare 国家查询返回禁止地区或无法访问，以测试监控。也可保留一条独立的管理连接作为对照；只改变 Claude 服务或 UDP 路由并不能触发此地区检查。
4. 等待运行检查发现异常。出口进入禁止地区，或严格模式下查询失败、无法确认时会触发阻断；页面或终端保持打开，但受保护程序的外部连接应失败。回到「安全检查」，选择对应对象并查看「网络已阻断」。测试期间也应确认控制连接或未受保护的其他程序是否仍符合预期。
5. 恢复路由器的正确网络后，再在对应对象上点击 **还原网络防护**。还原会移除阻断规则，仍在运行的旧程序可以重新联网，但不再由本次运行防护监控；如需继续受保护，请从启动器或 `claudec` 重新启动并恢复会话。

**如果路由器尚未修复，不要直接还原后继续使用旧进程**：规则移除后它可能通过当前网络直连。可以先保存并关闭受影响的进程，再还原规则。

## 恢复以前的 TUN 或代理模式

先在「安全检查」中分别还原仍存在的 Claude 或 CLI / Playwright 路由器运行防护；然后关闭「路由器模式」并保存，或执行 `claudec network-mode default`。最后为需要的对象重新选择并启用原来的 TUN 或固定代理防护，再重新启动受管程序。切换模式本身不会自动重建旧规则。

## 防护边界

- 检查并非实时：一次检查结束后约等待 10 秒，下一次探测最多等待 12 秒，系统繁忙时可能更慢；发现问题之前仍可能有流量。关闭「无法确认时也阻止启动」后，单纯无法确认的异常不会自动阻断。
- Windows 规则按当前用户和已登记的 EXE 生效，不是完整的进程树防火墙。同一 Playwright 浏览器 EXE 的其他实例也可能受影响；未登记的新版本、外部启动器、远程或容器浏览器、任意 shell 工具和系统 DNS 不在完整覆盖范围内。更新浏览器或 CLI 后重新启动受管会话，让程序重新登记。
- 为控制连接保留了本机 TCP 回环；本机其他服务可能转发这些连接。国家检查无法发现同一允许地区内的 IP 变化，也无法验证不同域名、IPv4/IPv6、UDP 或实际浏览器 WebRTC / TURN 是否走同一路线。
- 若监控组件退出，临时放行会消失，已登记程序的阻断规则保留。若显示「无法验证」，请检查网络防护状态，不要把它当作已经验证的阻断。需要进一步了解检查和规则时，参阅 [环境与网络防护说明](desktop-safety.md)。
